# 交付状态与证据边界

B 阶段五份真实文字验证计划累计 8 次尝试、4 条应用校验通过、4 条失败、2 条确认保存。第四份 strict b01 成功并保存；第五份 strict b02 正确定位相加错误并认可约分，用户确认保存后再请求 b06。b06 的新解答正确、JSON 结构有效，但把旧分析判为正确的约分标成“已订正”，与旧证据矛盾，整条订正被拒绝。b02 保持版本 1，没有追加订正或自评。累计输入 14,330、输出 5,524 token；人工评分为空，实际费用未知。重复调试题不是独立质量样本。

strict 格式约束不能保证前后判断正确。当前修订使用已保存旧分析中的错误步骤生成订正 schema：只有这些完整引用才可以声明 corrected/still_incorrect，其他变化只可 changed/uncertain；仍独立检查本次步骤证据，不自动改标签或删掉失败项。新增固定错误码区分旧步骤没判错与新步骤判断不匹配。订正提示词为 photo-correction-v5，strict 协议为 study-strict-output-v2，新约束只有本机验证，真实效果未知。默认仍是 json_object，没有 Agent 工具循环，详见[文字验证记录](STUDY_SMOKE.md)。

验证入口提供冻结计划、本机 HTTP 演练、持久调用记录、失败停止和确认保存，复用页面相同的服务与存储。普通页面尚未接入新 Agent 循环；真实照片与完整订正恢复尚未验收，本机演练不计作真实模型结果。

已实现双图录入、裁剪旋转、核对、分析适配、原文证据校验、错题收藏、订正对照、确认或放弃、知识点回顾、导出和回收站。提供固定题完整离线演示，使用独立存档。
