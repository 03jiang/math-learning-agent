# 代码怎样工作

程序按固定顺序处理输入、调用模型、检查回复，再由用户决定是否保存。模型负责提供分析，不直接修改文件，也不能上网、运行代码或判断学生已经学会。

仓库名中的 Agent 指这个带有人工确认的 AI 工作流。当前没有自主多 Agent 协作、模型训练或向量检索平台。

## 主要文件

| 文件 | 负责什么 |
|---|---|
| `study/images.py`、`study/photo_ui.py` | 上传、规范化、旋转和裁剪图片。每张不超过 8 MB；预览、应用调整和保存是分开的操作。 |
| `study/service.py`、`study/http_worker.py` | 发送文字及标明题目、作答用途的图片。请求体不超过 12 MB，有总超时限制，不自动重试。 |
| `study/diagnosis.py`、`study/corrections.py` | 检查 JSON 格式、原文引用和作答类型，限制没有依据的错误推断。 |
| `study/ui.py`、`study/correction_ui.py` | 展示分析和待保存的订正，让用户确认或放弃。输入或记录变化后，旧分析不能继续用于保存。 |
| `study/notebook.py` | 每题保存一个 JSON 文件，管理版本、重复操作、订正历史和回收站，兼容旧记录。 |
| `study/demo_service.py` | 提供固定题目的离线演示，只接受匹配的示例输入。 |

## 一次订正怎样保存

原作答和原分析保留不动。用户确认新订正后，程序追加一条记录，而不是覆盖过去的内容。

模型说“已经订正”的地方，需要分别引用旧分析里的错误步骤和新分析里的正确步骤。程序会检查这些引用，但不能只靠引用检查证明数学上真的改对了。

`reviews` 保存用户自评。保存模型的订正对照，不会自动增加一次“独立做对”，也不会添加掌握标签。

## 重复点击、旧记录和保存失败

未确认的草稿留在当前会话中；确认保存的内容，重启后可以恢复。

每次操作都有编号，同一个编号不会重复追加记录。保存前还会检查版本，避免旧请求覆盖后来的修改。文件锁用于协调写入，内容先写进临时文件，再通过原子替换更新正式文件。回收站只改变同一记录中的状态，不删除题目内容。

文件损坏时会提示，并保留原文件。请求超时后，不能确定服务端是否已经处理完成，所以程序既不自动重试，也不声称这次没有发生调用。

## 数据和密钥放在哪里

普通错题记录在 `data/study/notebook/`，演示记录在 `data/demo-study/notebook/`。密钥来自用户输入的当前会话或启动环境，不写进错题记录。

只有点击调用模型的按钮，才会发送本题相关内容。订正分析还会带上此前最近的作答和分析。公开导出会排除密钥、个人照片、错题记录、原始调用报告和本地 Git 历史。

目前使用 POSIX `fcntl` 文件锁，面向单机单用户，不是供多人共享的云端系统。Windows 原生运行、手机访问和在线部署不在本版验收范围内。
