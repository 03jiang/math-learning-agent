# 产品定义与验证计划

## 用户问题

设计假设：学生做错题后，常能看到正确答案，却不容易知道自己哪一步开始偏离、是概念还是偶然笔误，也难把订正整理成下次能用的方法。照片、参考解析和错题记录分散，增加了整理成本。

这些来自项目讨论中的场景假设，尚未进行用户访谈或真实学生验证。原型面向能在电脑上整理照片与文字的 K12 学生，教师或家长可以帮助核对解析。

核心任务：**“我有一道做错的数学题，希望看清自己与正确做法的差异，留下能在下一次解题时使用的总结。”**

## 核心流程与验收点

| 阶段 | 用户完成的事 | 产品提供什么 | 失败处理 |
|---|---|---|---|
| 输入 | 放入题目与原作答 | 双图、裁剪旋转、文字输入 | 无效图片不替换已有草稿 |
| 核对 | 确认符号、条件和作答归属 | 题干与作答分栏、明确作答类型 | 模糊处待核对，改输入撤销确认 |
| 理解 | 找到差异与依据 | 参考步骤、原文对照、错因假设和追问 | 只有答案不猜过程，缺条件先澄清 |
| 收藏 | 留下自己的总结 | 分类、错因、笔记、明确保存 | 未确认不入库，写入失败保留原记录 |
| 订正 | 再做、比较、决定是否保存 | 新旧引用、变化说明与历史 | 过期、重复、引用不符的更新拒绝 |
| 回顾 | 复习同类题 | 知识点汇总、自评、导出、回收站 | 自评和模型评价分开，不自动声称掌握 |

## 版本取舍

P0 是完整走通一题“输入—核对—对照—确认—订正—回顾”，以边界清楚和演示可复现为验收标准。先做显式确认与来源标识，再扩大题目范围。原四道分数题保留作受控评估，不用四题表现代表完整 K12。

P1 已补：双图、裁剪旋转、回收站、无需密钥的完整演示、公开源码和 CI。真实识图、人工教学评分按项目安排暂缓。

后续候选：移动端、多题拆分、复习计划、知识点标准化、同类题生成。应先验证当前流程的主要障碍，再决定排序；候选不等于已实现。

## 为什么需要核对与确认

错误答案也是证据。若识图直接把原错答订正，再交给分析，就丢掉了学生真正的错误过程。识别、核对、分析与保存分开，让用户能够检查每个阶段，也便于定位失败和撤回。

错因采用“可能”和追问，引用学生原文，不把单题错误变成能力标签。格式与引用校验不等于数学正确性，仍需教师核对。

## 指标设计：待验证，不预填成绩

| 指标 | 定义 | 方法与限制 |
|---|---|---|
| 输入到可分析耗时 | 放入题目至完成核对的时间 | 任务观察，拆分等待、修改和操作耗时 |
| 转录准确性 | 数字、符号、图形条件和作答归属的正确比例 | 人工标注，按清晰度与题型分组 |
| 差异定位有效率 | 指出最早关键错误且证据可对应的分析占比 | 独立人工评分；加入等价解法、答案单独给出等反例 |
| 收藏完成率 | 查看分析后明确保存的用户数 / 查看结果的用户数 | 待埋点；低值也可能表示已理解或不信任，需访谈解释 |
| 订正闭环完成率 | 保存新作答对照的题数 / 待订正题数 | 预先确定观察窗口，排除演示数据 |
| 同类题迁移 | 延迟后独立解决同类新题的表现 | 需要研究设计和对照，不用照抄正确答案代替 |

目前没有真实用户数、留存、满意度或学习提升数据，也没有默认行为埋点。测试通过数只说明已覆盖的软件行为。

## 下一轮实验

先用 13 个合成图片场景和真实手写样本验证识图与分析，请教师核对转录、数学、证据与建议，记录失败和版本。再做小规模任务观察，比较只看参考答案和步骤对照后的订正体验；样本量与成功标准在招募前确定。

优先回答：核对是否过重、学生能否找到第一处错误、总结能否帮助下一道题。证据足够后再投资移动端与自动复习推荐。
