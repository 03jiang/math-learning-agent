# 为什么做这个错题助手

看到正确答案，不一定就知道自己错在哪一步。这个项目想尝试的是：把题目、学生原来的解题过程和后来的订正放在一起，让学生可以逐步对照，也方便以后复习。

这还是一个待验证的想法，不是用户调研结论。目前没有做过用户访谈或真实学生测试。原型按小学、初中、高中的数学整理场景设计，使用者需要能在电脑上处理照片和文字；有疑问的解析仍然需要教师或家长帮助核对。

## 一道题怎样走完流程

先上传题目和自己的作答。两者在同一张照片里，可以只传一张；分开拍的，可以分别上传。图片支持旋转和裁剪，也可以直接输入文字。

接着核对识别结果，尤其是数字、符号、图形条件，以及哪些文字是学生写的、哪些是教师批注。这里要保留原来的错误过程，不要提前改成正确答案。否则，后面的分析就看不到学生当时究竟写了什么。

核对后，查看参考解法和原作答的逐步比较。系统可以提出可能的错因和进一步检查的问题，但不能只凭一道题给学生下结论。只有最终答案时，不推测中间的错误；条件不够时，先请用户补充。

最后，由用户决定是否加入错题本，补充自己的提醒。重新做题后，可以看前后变化，再选择保存或放弃这次订正。旧作答不会被替换，误删的题目也可以从回收站恢复。复习情况由用户自己记录，不因一次答对就自动标记为“已掌握”。

## 这一版先做什么

先把一道题从输入到复习的过程做通，再扩大题目范围。核对、确认保存和查看来源放在前面，是为了让用户能发现错误，并且保留不保存的选择。

目前已加入双图上传、裁剪旋转、回收站、无需密钥的完整演示、公开源码和自动测试。真实识图与人工教学评分还没有完成。早期四道分数题继续用于范围较小的评估，不能用四道题的表现代表整个中小学数学。

手机端、一张照片拆成多道题、复习计划、统一知识点分类和同类题生成都还没做。是否继续做这些功能，要先看当前流程哪里最难用，而不是把功能越加越多。

## 为什么多加一次核对

假如识别照片时把学生的错答直接“修正”了，后面的分析再完整，也不是在分析学生原来的过程。把识别、核对、分析和保存分开，能让用户逐步检查，也更容易找到错误发生在哪一环。

代价是操作步骤变多。后续要观察用户是否愿意核对、核对要花多久，而不能只因为设计了确认按钮，就认为控制权的问题已经解决。

程序会检查模型引用的文字能不能在原作答里找到，但这只能检查引用，不能证明数学判断正确。错因仍以“可能”呈现，并保留需要教师核对的说明。

## 接下来要看哪些结果

| 想知道的问题 | 计划怎样检查 |
|---|---|
| 从上传到能开始分析，要花多久？ | 观察操作过程，分别记录等待、修改文字和点击操作的时间。 |
| 题目和作答识别得准不准？ | 人工核对数字、符号、图形条件和文字归属，按题型与图片清晰度分组。 |
| 有没有找到第一处关键错误？ | 请人独立检查分析和原文是否对应，加入等价解法、只有答案等容易误判的情况。 |
| 用户看完分析后会不会保存？ | 计划统计保存人数占查看分析人数的比例。目前没有埋点；不保存也可能是已经理解或不信任结果，需要追问原因。 |
| 用户有没有完成再次作答并保存订正？ | 在预先确定的时间内，统计保存订正的题数占待订正题数的比例，排除演示数据。 |
| 订正以后，能不能独立做出类似的新题？ | 需要延迟测试和对照研究，不能把抄对当前答案当作已经学会。 |

这些是计划，不是已有成绩。目前没有真实用户数、留存、满意度或学习提升数据，自动测试通过数也不能替代这些结果。

## 下一步

先用已经准备的 13 个合成图片场景，再补充真实手写样本，检查识图和分析。请教师核对转录、数学内容、原文引用与练习建议，记录错误及对应版本。

之后再安排小范围的操作观察，比较只看参考答案和看步骤对照时的订正体验。招募前确定样本量与判断标准，重点看核对是否太麻烦、学生能否找到第一处错误、留下的总结能否帮助做下一道题。再根据结果决定是否开发手机端或复习推荐。
