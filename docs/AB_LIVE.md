| 预算提案 | 新预留2元；按完整请求字节上限的保守估算约1.63元，实际账单未知 |

费用按2026-09-24核对的[DeepSeek官方人民币价格](https://api-docs.deepseek.com/zh-cn/quick_start/pricing/)：`deepseek-flash` 高峰、输入缓存未命中2元/百万token，输出8元/百万token。继续使用官方 [Chat Completions](https://api-docs.deepseek.com/api/create-chat-completion/)；显式关闭thinking，温度0.2，输出上限4096。A/B使用相同配置。

每次请求限制64000 UTF-8字节，按该字节数近似输入token，另留1024协议token；不是供应商tokenizer。每次最高估算 `(65024×2 + 4096×8)/1,000,000 = 0.162816` 元，10次为1.628160元。不使用缓存优惠或闲时折扣降低预留。程序限制次数和**估算金额**，不能保证供应商账单严格封顶；如返回用量超过估算假设，当前请求仍可能已计费，程序停止后续调用。

新提案与旧B阶段的13次调用及1元预算分开，尚未批准。工具日志里的演练计数不是已消费的真实API次数。

## 无密钥准备和演练

在项目根目录、已安装依赖的Python环境中运行；目录必须不存在：

```bash
# 默认只预览两道开发题，零HTTP、无需密钥
python -B -m tools.evaluate_agent_live preview --output evaluation_runs/ab-live-preview-v1

# 同一执行账本连接本机手写HTTP回复，不能升级成真实计划
python -B -m tools.evaluate_agent_live local --output evaluation_runs/ab-ledger-local-v1

# 只读状态：无需有效旧价格、无需密钥、不会改写报告或重发
python -B -m tools.evaluate_agent_live status --directory evaluation_runs/ab-ledger-local-v1

# 空表汇总；本机响应、失败和未运行行禁止填模型质量分
python -B -m tools.evaluate_agent_live scores --directory evaluation_runs/ab-ledger-local-v1
python -B -m unittest test_agent_evaluation_live -v
```

新计划可用 `--cases e03,e11,e12 --budget-cny 3` 明确选择开发案例。双方方案和该案例所有回合必须一起纳入，不能只跑较优的一方或跳过已计划的追问。创建时检查完整上限估算，预算不足直接拒绝，不擅自提高额度。保留集 e21–e30 当前不允许进入这个开发入口；后续需先记录策略冻结与开发/保留使用声明，再单独准备保留集执行。

`PLAN.md`展示具体提案，`manifest.json`固定代码提交及哈希、模型参数、案例、笔记/历史文件哈希、价格与额度。`previews/`仅是输入骨架；实际追问依赖真实前序回复，工具结果由执行决定，不在预览伪造。`scores.json`放人工参考和标准，程序用白名单构造模型输入，不发送这些评分字段。

`rows/`记录每次实际请求、哈希、请求前预留金额、HTTP状态、用量、限长原始正文、错误码与说明、实际收到的资料和任务状态。只保留对外正文及工具行为，不记录模型内部推理或密钥。未知用量/费用保持null；按已报告token算出的高峰估算与实际账单分开。

## 批准后才执行

先确认具体 `PLAN.md`、完整计划编号、最大请求数和新预算。以下是命令格式，**不是本轮已执行的命令**：

```bash
python -B -m tools.evaluate_agent_live run \
  --directory evaluation_runs/ab-live-preview-v1 \
  --confirm-plan "已确认的完整计划编号" \
  --max-model-requests 10 --budget-cny 2
```

只在本机交互终端用隐藏输入提供密钥；不支持密钥参数、环境读取、文件读取或聊天输入。检查范围、预算、版本、已有执行状态和TTY后才询问密钥。已完成的重复命令只返回状态，不再问密钥；已有失败或中断则拒绝继续。

计划24小时内且在同一UTC日有效，避免历史过期过滤发生变化。价格快照7天后拒绝真实预览/执行，需重新核对、更新版本和确认新计划；不后台拉取价格或自动重建计划。真实执行要求干净的已提交版本，代码、配置或输入改动使旧计划失效，旧报告仍保留可读。

## 执行和重启边界

1. 获取整份计划的独占锁，核对明确批准的范围；本机计划与真实模式不能混用。
2. 每个回合从同一题干、作答和偏好生成输入；先前回复来自实际结果。选择下一步但上轮没有可选任务时停止，不伪造选择。
3. 每次HTTP发送前重新检查冻结输入、生成参数、字节/次数/估算金额，并原子写入预留账本。预留失败则不发送。
4. 失败立即停止整份计划，后续行保留pending；不跳过、不自动重试、不自动续跑。未知请求仍占额度，不自动退款或回收名额。
5. 崩溃可能留下running/unknown。新Python进程能读回状态和已完成回复，但不能据“没拿到回复”重新收费调用。
6. 评估无收藏、订正保存或掌握写入入口；种子历史只在隔离目录中生成，执行期间不变。人工评分独立填写，空白不是通过。

主要代码：`study/evaluation_live.py`（冻结、账本、核对、预算、状态）、`tools/evaluate_agent_live.py`（预览/本机/显式真实入口）、`study/evaluation_scoring.py`（两类报告及人工评分）。A继续复用`FixedWorkflowService`，B继续复用`AgentStudyService`；这一步没有修改教学策略以追求更高分。
