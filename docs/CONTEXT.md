# 主页面的设置、同题追问与历史边界

阶段 D 的共享逻辑已接到照片分析和订正页面，也用于普通单次请求和可选 Agent 循环。当前仅做离线程序验证；本轮新增真实模型请求为 0。提示是否适量、是否漏答案、讲解质量及检索材料是否被正确使用，仍需真实回复与人工检查，不能由通过测试推断。

## 从主页面使用

在草稿 PR 分支 `feat/study-smoke-audit` 运行 `python -m study.launch`，尚未合并到 `main`。在侧栏“长期学习设置”选择步骤大小、解释方式、信息密度，点击“确认保存长期设置”才生效。三项选项沿用旧设置定义；其余三项没有接入照片流程，因此不显示。旧模块按题保存的设置不自动迁移，也不冒充全局画像。

核对题目和原作答后，展开“本轮讲解要求”：可以写“这次详细一点”，也可临时覆盖三项设置。点击“分析这道题”生成完整分析；点击“只给一个提示”或“继续讲解”进行同题追问。订正页另有“比较本次订正”，沿用本题前后原作答。只有答案时仍不应猜解题过程，原有完整分析的证据校验与确认保存规则保留。

本轮要求和临时覆盖用于下一次成功请求，随后清空；失败保留输入供检查，缓存错误，不自动重试。临时选项不写设置文件，不从自然语言自动提取长期偏好。完整分析需要完整参考解法；“引导式说明”是解释风格，只有独立的“只给一个提示”请求要求暂不给最终答案。

追问使用独立的 `study-coaching-v1` JSON：`status`、`reply`、`next_step`、`clarification`，不允许完成、掌握或设置更新字段。普通模式单次请求，可选 Agent 模式仍最多四次模型请求、三次只读工具调用，不能自动扩大额度。支持 JSON 正文及原可选 strict 返回格式；真实服务对新增追问协议的遵从性未验收。

收到回复后，补充一个问题或选择下一步，再发起下一轮；重绘和重复点击同一请求复用已有结果。“把这一步作为接下来的任务”只把状态设为 `next_step_selected`，已完成列表仍为空，不写错题本、自评或掌握。追问不能直接变成诊断存档，需要收藏时仍使用原来的完整分析和确认流程。

## 什么会保存、什么时候失效

| 内容 | 存放位置 / 生效范围 |
|---|---|
| 确认过的长期设置 | 当前数据目录 `learning-settings.json`；跨题生效，重启可读。单机共享数据目录，不是账号级用户画像 |
| 逐题历史使用权限 | 同目录 `history-controls.json`；显式确认后生效，不修改原错题文件 |
| 本轮要求与临时覆盖 | 浏览器会话；成功后清除，换题清除，不写长期设置 |
| 同题近期对话、选择的下一步 | 浏览器会话，最多四轮，24 小时内；换题、改作答、切换历史权限、资料变动后清空 |
| 原作答、完整分析、订正、自评 | 仍由原 Notebook 明确确认后保存；此次没有迁移或改写旧档案 |
| Agent 执行记录 | 私人 `agent-runs/`；可能包含题目、要求、近期对话和工具结果。无密钥或内部思维链，不作为学习掌握证据 |

普通目录默认为 `data/study/`，演示目录独立；自定义入口按 Notebook 的父目录存设置。读取默认值不创建文件；重复保存相同设置不推进版本，旧版本的冲突写入被拒绝，损坏文件不覆盖。关闭浏览器后可恢复确认过的设置和错题本，临时对话及待做任务不恢复。

## 每次请求的组织与预算

优先级为：当前核对后的题目和原作答 → 本轮要求 → 确认过的设置及本轮覆盖 → 本题待做任务 → 必要的近期对话 → 模型按需读取的笔记或跨题历史。原题干、符号、作答保留原文。订正所需前一份作答和模型分析属于本题上下文，并明确标为待核对模型意见。

`learning` 分开保存 `confirmed_settings`、`temporary_overrides`、`effective_settings`、`turn_request`、`task` 和 `recent_dialogue`，不把整段聊天或全部错题预先塞入请求。模型不得将过往对话中的“这次详细”延续成下一轮设置。

| 预算 | 规则 |
|---|---|
| 组装后的题目上下文 | 最多 40,000 UTF-8 字节；近期对话从最新开始按完整轮次保留，超限整轮省略，数量写入 `context_budget.omitted_dialogue` |
| 整个模型请求的文字部分 | 最多 64,000 UTF-8 字节，含系统提示、schema、工具定义及工具返回消息；每次发送前检查 |
| 图片与总 HTTP 请求 | 图片单独验证，完整请求仍受原 12 MiB 传输上限约束；不把 base64 字节冒充视觉 token |

这是字节预算，不是 tokenizer 计数、模型上下文窗口或费用封顶。优先内容自身超限时请用户缩小范围，绝不静默裁数学条件；工具结果使后续回合超限时停止，不发送下一次模型请求。历史和笔记允许带有明确来源标识的节选，不走当前原文裁切。

## 历史使用和旧分析修正

跨题历史默认关闭。关闭时不提供历史工具、不读取历史控制文件/正文用于请求；之前可能含历史的同题回复缓存也失效。页面展示错题本本身的本地读取与模型取历史是两个操作。本题订正所需的前次作答不属于跨题历史。

允许查询时仍排除当前订正题、回收站、无关条目、用户停用的条目，以及超过 180 天未更新的条目。180 天是明确的工程窗口，不代表数学知识在 180 天后变错；同分时优先较新记录。日期窗口、权限和资料版本进入缓存签名，停用或归档后的内容不能靠旧回复继续带入下一请求。

在错题本展开“这道题作为历史资料”，可以停用整条历史，或仅停用旧模型分析。原作答保留；在“订正笔记”填写的修正会标为用户自述，与旧模型意见分开。模型只能提示冲突待核对，不得将某次旧错因变成永久能力标签，也不会改写已存分析来制造进步。

课程笔记仍是关键词检索：本轮增加了长笔记的相关句段选择，避免永远只取开头 360 字符。历史查询过滤“计算、题目”等泛词，并要求知识点命中或多个题干词命中。测试检查通分、整体概念对应的笔记及支持性原句、陌生词无结果、长笔记中的相关段落；这不等于语义检索质量评估。引用逐字可追溯与内容支持推理是两回事，后者待 E 阶段人工评分。

## 无密钥复现

在仓库根目录执行，演练输出目录必须不存在：

```bash
python -B -m tools.demo_study_context --output evaluation_runs/context-offline-01
python -B -m unittest test_study_context test_study_context_ui -v
python -B -m unittest discover -v
python -m study.launch --check
```

终端演练实际运行三次本机 HTTP 手写响应，展示未确认不写设置、临时覆盖失效、同题追问、选择待做任务、换题清空和设置重读。不能当作真实模型决策或教学效果。固定方程题完整离线演示入口保持原样，禁用新增设置和追问，不伪造针对任意设置的响应。

核心文件：`study/preferences.py` 管确认与原子保存；`study/context.py` 管组装、时间、字节预算与状态；`study/context_ui.py` 是照片和订正页共用交互；`study/service.py` 和 `study/agent.py` 执行同一上下文；`study/agent_tools.py` 管历史权限与时效；`retrieval.py` 管笔记片段选择。新增测试覆盖真实主页面按钮、本机 HTTP、失败缓存、来源失效和新进程恢复。
