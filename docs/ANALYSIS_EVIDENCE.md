## 只有答案时

`study/evidence.py` 定义四条与 verdict 对应的固定反馈，分别说明结果相符、不符、未完整回答或还需核对，并明确“仅有答案，不能判断计算过程，请补充步骤”。题目、学生答案、参考答案和参考解法仍分别展示。

严格返回格式通过 enum 限定这四条反馈；应用再次核对反馈与 verdict 是否对应。普通 JSON 模式也执行相同应用校验。不能在句子前后追加推断，应用不会静默删除模型文字来伪造通过。摘要、步骤、归纳和追问等其他文本另检查常见的明确过程归因表述；正常的参考通分说明和补步骤问题可以保留。

这项设计缩小了答案反馈的表达自由，避免只把禁止推断的规则写在提示词里。其他自由文本的表述检测属于有限规则，**不能覆盖任意语言表达或证明整体语义正确**。仍需内容审核，不能据此宣称消除了所有幻觉。

## 有步骤时

步骤引用必须包含等号两侧，不能用 `= 2/6` 这种片段充当独立错步。复用项目已有的 `step_check.ArithmeticParser` 与精确 Fraction 运算，检查受限数值等式的局部成立性，不使用 eval。

例如 `1/2 + 1/4 = (1+1)/(2+4) = 2/6`：

- 第一段 `1/2 + 1/4 = (1+1)/(2+4)` 不成立。
- 第二段 `(1+1)/(2+4) = 2/6` 成立，但承接了前一处错误。
- 整体作答仍错。不能把两段混在一条引用里都标错，也不能因为后段成立就说整体正确。

混合成立与不成立等式的连等式要求拆开引用。与受限数值检查冲突的肯定判断被拒绝；`uncertain` 不会被自动改成肯定判断。

支持范围是有界的数字、分数、小数、正负号、括号与四则运算。变量、文字证明、几何关系、超长算式、无法解析的表达等不由此规则自动判对或判错；模型判断和人工核对仍有必要。规则检查局部运算，不能保证题目条件、建模、知识点或参考解法正确。

## 保存与历史记录

新分析、订正、接受候选和新增收藏均检查当前规则。失败保留原始诊断内容，记录固定 validation_issue，不创建有效候选、不自动重试或保存；候选若被手动篡改也不能绕过接受检查。

已有存档兼容读取，不重写旧回复或把旧评分当作新版校验结果；重复保存同一旧记录仍幂等。新增一份旧内容则需满足当前规则。存档中的历史订正按原结构读取，新追加的订正仍要通过当前规则。

| 错误码 | 意义 |
|---|---|
| `answer_only_feedback_not_bounded` | 仅有答案时反馈不是与 verdict 对应的固定句子 |
| `answer_only_method_claim` | 其他讲解文本出现规则覆盖的无依据过程归因 |
| `step_quote_incomplete` | 引用缺少等号一侧 |
| `step_mixed_equalities` | 引用混合成立与不成立的数值等式 |
| `step_arithmetic_verdict_mismatch` | 局部步骤判断与受限数值检查冲突 |
