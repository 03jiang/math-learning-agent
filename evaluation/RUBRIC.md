# 人工评分说明 v1

本表评价模型回复，不能推断儿童的学习增益。`scores.csv` 每行对应一份回复；两种提示词分别评分。`review.md` 给出逐行请求、回复和检查重点。可以用文本编辑器或表格软件填写 UTF-8 CSV，保持列名、行 ID、用例和回复路径不变。

先看请求中的题干、学生输入、读题结果和有效设置，再看回复 JSON 中的 `round.reply`。`reply_valid` 只表示字段与权限校验通过。教师仍需核对解释、提示分量及引用语义。

| 列 | 0 分 | 1 分 | 2 分 |
|---|---|---|---|
| `math_correctness` | 有数学错误，或把错误步骤/错误整体判断为正确 | 结论基本正确但理由含糊、缺必要条件 | 数值、单位、整体与解释正确；如有错误步骤，明确指出 |
| `support_fit` | 忽略当前困难、否定学生或直接宣称掌握 | 有关但太泛、过量或下一步不可执行 | 对应当前错误/疑问，解释适龄，给可执行的一步 |
| `reading_understanding` | 忽视错选、沿用错误整体，或把未选当错答 | 提到读题但未定位具体哪一问 | 准确使用选项及错问 ID；对应题干解释；相符时不反复误判 |
| `settings_match` | 严重违反有效设置，如 hint 直接泄露最终答案 | 大体符合，但一项或多项明显不足 | 六项适用设置均得到合理体现，帮助程度相符 |
| `source_fidelity` | 编造引用、歪曲笔记或声称来源支持无关结论 | 引用内容基本准确，但与当前解释关系含糊 | 使用笔记时语义忠实、引用对应；无需引用的独立解释不伪装来源 |

`reading_understanding` 无读题记录时预填 `NA`；`source_fidelity` 无参考笔记时预填 `NA`。其余项不得自行设为 NA。完整的正确读题选择仍需评分，评价是否被准确使用、没有误判。

- 空白表示尚未评分，不是 0 分；数值只能填 `0`、`1`、`2`。
- 填数值时同时填写 `reviewer`。`notes` 写出对应句子及理由；0/1 分尤其需要说明。
- 失败、预览、未运行、完成情况未知的行保留空分，只在备注记录运行问题。错误率另外报告。
- 不把“没有状态被写入”混入数学正确分。这是本地程序的独立工程保证。
- 完整填写一对回复后，才纳入成对均分。报告同时显示未评分数和失败数，避免只展示成功样本。
- 尽量先独立打分，再看两版对照。当前表暴露 variant，不声称盲评；若只有项目作者评分，材料中标注自评。

先使用开发集观察问题，改动后新建报告并重新冻结。保留集每个题目/输入情景组与开发集分离，但仍是同四道题，不能称为独立学生数据或新题泛化测试。第一次查看保留集真实回复后，如据此改 prompt，该组不再作为未见过的保留评估；需新建用例并如实记录。

最终报告应包含模型 ID、配置、提示词/用例哈希、运行日期、每版有效与失败数、评分人、完整配对数和均分差。单轮、48 条合成用例和人工自评不足以证明统计显著性、学习增益或整个 K12 的适用性。
