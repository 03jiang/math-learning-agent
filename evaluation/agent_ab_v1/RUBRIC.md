# 逐回合人工评分 v1

先看核对题干、学生原作答、本轮要求，再看实际回复、工具返回与引用。每个案例、方案、回合在 `scores.json` 各一行；人类参考只在检查表中。不得因为字段合法、引用逐字匹配或流程停止安全，就直接给教学高分。无需输出内部思维链。

| 字段 | 0分 | 1分 | 2分 |
|---|---|---|---|
| math_steps | 数学/单位错误、把正确局部运算标错、捏造学生步骤 | 主要结论对但步骤遗漏或说明不够可检验 | 当前帮助模式允许的数学陈述正确；认可等价方法，逐步对照可靠；条件不足时正确澄清 |
| help_fit | 违背提示要求直接泄题、帮助无关，或一律拒答 | 部分相关但过量/泛泛，缺少可执行下一步 | 对应本轮困难、帮助分量适当、可执行；临时设置过期，选择任务不标完成 |
| tool_use | 越权/无关/反复调用，或明需查旧记录却装作查过 | 工具有些价值但查询范围/次数不适当 | 按需查询或合理不查；没结果/工具失败如实说明，仍在能力内帮助 |
| source_support | 编造来源或引用不支持结论 | 摘录确实存在但相关性/语义支持不足 | 实际资料相关，解释忠实，引用支持对应结论 |
| history_use | 无关/停用/过期历史进入判断，旧错误被当能力标签 | 相关历史被过度使用或来源区分不清 | 尊重授权和时效，区分用户作答/旧模型意见，对本题确有帮助或合理不使用 |

`math_steps` 看具体语义，不强制与参考使用相同解法/措辞。只有答案不能推断学生采取的算法；发现步骤错误也只能提出带核对问题的错因假设。整题建模错误与等式局部运算错误分别判断。提示回合不要求报最终答案，错误泄题影响 help_fit。

填写规则：

- 每格仅 `null` 或整数 `0/1/2`；空白是未评分，不是0分。无来源时 source_support 保持 null；历史未授权时 history_use 保持 null。
- 填分或标 unsupported_inference 时，必填 reviewer、reviewer_role（developer_self / independent_teacher / independent_peer）和 evidence。证据写原文片段、来源编号/回合与判断理由。
- unsupported_inference 单列 null/true/false，不藏在均分里；只对实际复核过的行填 true/false。证据不足归因、编造隐含步骤等写明原话。
- disagreement 保留第二位评审的分歧、理由与最终处理；当前表不声称盲评。只有开发者打分时必须标为自评；独立复核另保留原评分表副本，不能覆盖第一位评审。
- 保留固化的 row_id、case_id、arm、turn_index、reference、checks。范围变化需新计划，不在评分时改标准。
- 预览、未运行、失败、完成未知或本机手写响应不能填模型质量分。失败另在可靠性分母中报告。运行 errors 与教学分不能互相替代。

汇总同时显示计划总行数、实际完成/失败/阻塞/未运行、HTTP/工具次数、时延、已报告token与用量覆盖率、人工已评数量/覆盖率。缺失用量不补0、未知费用保持null。每个维度只对**双方完成且同一维度都有评分**的配对计算 B−A；保留配对数，不能删掉失败分母只展示均分。多轮同题的分数相关，不作独立样本显著性检验。

最终报告需记录：案例/家族数、版本/配置/日期、原始报告路径、每版请求和失败数、配对数、评分人角色、争议、失败例子与内容证据、改动前后、权衡，以及保留集是否已用于调参。本轮所有教学分为空；没有准确率、教师评测或学习提升结论。
